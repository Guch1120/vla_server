# 物体付きシーンの検証（2026-10-15）

実機は接続していない。kotyaka-websimのPiper専用 `vla_pick_place` プリセットを使用する。
支持台・赤い把持対象・青い比較対象・緑の配置先を配置し、
シミュレータ側でMJCFの挿入マーカー誤一致を修正した。
シーンの位置・準備姿勢・検証はシミュレータの `docs/PIPER_VLA_SCENE.md` に記載。

推論入力は実際のブラウザMuJoCoからROS 2 Humble / rosbridgeを通して取り込んだ。
`configs/bridge.piper_sim.example.yaml` によりモデル `mock_piper_rgb6` を選択し、
画像・6関節・独立したグリッパ位置・シミュレーション時刻をHTTP APIへ渡す。
出力先は `/vla_bridge/dry_run_actions` のみ。

観測開始姿勢で3種類のタスク物体が実際の640×480カラー画像に写った。
20秒間に画像15件・関節32件・dry-run応答4件、API例外0件。
検証終了時の状態はHOLD（応答後の待機を含む）で、継続制御の性能合格を意味しない。
RGB/整列深度/CameraInfo/点群の対応検査もPASS、各18件・566点の再投影誤差は0.001画素未満。
Web側はDocker内249テストとTypeScript/Viteビルド成功。

この検証はVLAによる物体操作の合格ではない。現在のレジストリは全モデルが
`synthetic:zeros-v1`、trained=false。ACT/Diffusion Policy/π₀.₅のAdapter、
Piper用学習済み重み・正規化統計・データセット、グリッパを含む実行器が不足している。
ダミー出力やIK・専用物体の把持latchをタスク方策として代用しない。
WP01/WP02の通信検証と、WP03以降の実行器・学習済み方策の検証を区別する。

実機相当として未確認なのは、実機校正値、摩擦・質量・衝突近似の同定、
実機ドライバの指令インターフェースとの実行器互換性、停止・切断時挙動、
学習済み方策による閉ループの把持・配置成功率である。
